# Requirement Analysis Skill

面向 ChatGPT 与 Codex 的可复用需求分析工作流。从 PRD、表格、文档、原型、会议记录或已有代码上下文出发，生成证据可追踪的需求分析成果。

## 能力

- 需求完整性、歧义、冲突、权限、数据和非功能风险扫描；
- 结构化需求基线与人工澄清关卡；
- 领域模型、逻辑表结构、候选 DDL 和数据库评审关卡；
- 前端、后端、数据库、测试和运维研发任务拆解；
- 验收条件、测试点和双向追踪矩阵；
- 新旧需求版本的变更影响分析；
- 大型需求分批处理和中断续跑；
- 可选择的外部标准或市场调研策略，默认不联网。

## 目录

Skill 位于：

```text
.agents/skills/requirement-analysis/
```

其中包含：

- `SKILL.md`：触发条件、模式路由和主工作流；
- `references/`：各阶段操作规则；
- `assets/templates/`：标准输出模板；
- `scripts/`：输入清点、模式路由、案例初始化和追踪校验脚本；
- `agents/openai.yaml`：显示名称和默认调用提示。

## 使用

在仓库目录启动 Codex 后，可以显式调用：

```text
使用 $requirement-analysis 分析这份需求，自动选择模式，并在人工关卡暂停确认。
```

也可以直接描述任务，例如：

```text
检查这份 PRD 是否存在遗漏、冲突和权限风险。
```

```text
根据这份需求设计领域模型和数据库表结构，并拆分研发任务。
```

Codex 也可以依据 `SKILL.md` 中的 `description` 自动选择该 Skill。

## 工作模式

| 模式 | 用途 |
|---|---|
| `scan` | 需求审查、风险扫描和澄清问题 |
| `full` | 需求基线、数据设计、任务、验收和追踪 |
| `change` | 新旧需求版本差异与影响分析 |
| `resume` | 根据状态文件从未完成阶段继续 |

## 安全边界

- 外部研究默认关闭，必须明确授权后才能检索标准或市场方案；
- AI 推断、外部资料和人工确认必须分开标记；
- 未通过业务关卡时不生成正式需求基线；
- 技术条件不足时不臆造生产表结构或 DDL；
- Skill 不连接生产数据库，也不执行 DDL；
- 原始需求、敏感数据和真实案例不包含在本仓库中。
